# 03 界面设计

状态：已实现（Fluent 2 外壳，2026-11-25）
对应需求：FR-101–199（编号段见 [00 设计基线](00-design-baseline.md) §14）
原则：URL 即状态、状态真实、危险可见、窄屏可用、全键盘可达

本文只写**布局、交互、响应式**。页面 ID、路由、字段名以 [00 设计基线](00-design-baseline.md) §5/§6/§7/§9/§10 为准；数据契约见 `05-backend-contract.md`，token 见 `06-design-system.md`，安全边界见 `07-security.md`。语义继承 [`tui/docs/03-ui-design.md`](../../tui/docs/03-ui-design.md)，本文是其浏览器版本的等价物。

### 1.2 区域职责

| 区域 | 承担 | 不承担 |

## 2. 路由与 URL 即状态

选中 provider、时间范围、日志过滤、表格排序**全部**进 search params（可分享、可回退）。

| 参数 | 页面 | 取值 | 默认 | 说明 |
|---|---|---|---|---|
| `provider` | providers/quota/accounts/logs/diagnostics | `qoder-cn`…`raccoon`、`gateway` | 无（不选中） | 跨页跳转保留同值 |
| `q` | overview | 任意文本 | 空 | provider 名称/ID 搜索 |
| `range` | usage、reports、gateway/usage | `24h` `7d` `30d` `all` | `7d` | 总览 KPI 卡与用量页同源同参 |
| `model` | usage | 模型键 | 空 | 打开模型详情抽屉 |
| `lines` | logs | 离散档位 `200` `500` `2000` | `500` | 上限 2000，超出显示截断提示 |
| `filter` | logs | 任意文本 | 空 | 只作用于已加载文本 |
| `follow` | logs | `1` `0` | `1` | 手动向上滚动自动置 `0` |
| `sort` / `dir` | overview/providers/usage/gateway* | 字段名 / `asc` `desc` | 各页固定默认 | 与表格列一一对应 |
| `panel` | 全部 | `provider` `task` `account` | 无 | 打开右侧抽屉；`Esc` 清空 |

1. 参数是**状态**不是请求缓存：刷新页面必须还原同一视图。
2. 非法/未知取值回退默认值**并提示一次**，不静默丢弃，也不报整页错误。
3. 排序、过滤等连续变更用 `replace` 语义避免污染历史；页面跳转用 `push`。
4. `--demo` 由桥接决定并写入 `env`，不与 local 数据混在同一语义里。
5. token、绝对路径、账号 key 明文不进 URL；账号以脱敏值或索引引用。
## 3. 逐页设计

每页固定回答五个问题：**顶部指标**、**主区域**、**详情区**、**可用操作**、**异常入口**。
### 3.1 `overview` `/`

```text
┌ 概览 · 只读视图                                                   [刷新] ──┐
│ 运行/启用 5/8   配置漂移 1   认证告警 1   可领取/告警 1/2                   │
├ 服务拓扑 ──────────────────────────────────────────────────────────────────┤
│ qoder-cn → codearts → trae-local → … → 统一网关 :8785 → 客户端            │
├ Provider 矩阵（筛选/排序）──────────────┬ 右栏（≥1280px 并排）─────────────┤
│ Provider  on 进程 认证 客户端 端口 模型 额度 漂移                         │
│ Qoder 国内 ●  ●   1天  已写入  8789  11  ▓▓▓░   —                         │
│ CodeArts   ●  ○   正常 未写入 10087   —   ▓▓▓▓   停止                      │
│ …                                                                          │
│ 选中行 → 详情抽屉（完整字段/pids/control/下一步）                         │
├ 待处理 ────────────────────────────────────────────────────────────────────┤
│ ! codearts：开关=开、进程=停止 → [启动] [查看日志]                         │
├ 用量指标 · 近 7 天（与 /usage 同源）────────────────────────────────────────┤
│ 会话/提示 · 会话步骤 · Token 构成 · 工具成功率；下方 7 天趋势面板           │
└────────────────────────────────────────────────────────────────────────────┘
```

- 顶部四个 KPI 瓦片：`运行/启用`、`配置漂移`、`认证告警`、`可领取/告警`，其中 steps 类趋势只画真实活动点。
- 口径：`已启用`=`on=true` 数；`运行`=`up=true` 数（与前者独立计算）；`认证提醒`=`auth.state ∈ {expiring,expired,missing,unknown}` 数；`配置漂移`=派生 `drift` 非空数；`可领取`=后端显式 `claimable` 数（未知不计入）。
- 服务拓扑条按 `provider → 网关 → 客户端` 展示，纯只读示意，不代表请求链路追踪。
- 主区域：九家白名单 + `gateway` 的紧凑矩阵，含 on/up/oc/auth/drift 状态点与开关、进程、客户端、端口、模型数、额度条、漂移 badge；保留筛选、排序、URL 状态与详情抽屉。
- 宽屏右栏：健康度环、额度 Top、近 7 天 sparkline、待处理事项；`>=1280px`（Tailwind `xl`）并排，窄屏落在主区下方。
- 详情区：选中行完整字段、`pids[]`、`control`、最近操作与下一步。
- 可用操作：跳转（进服务/额度/账号/日志/诊断并保留 `provider`）、页内刷新；**本页不直接写操作**。
- 异常入口：漂移条、认证提醒、额度 `error`、用量 `stale` 各给一个可点击的"下一步"。
### 3.2 `providers` `/providers?provider=codearts`

```text
┌ 顶部指标：运行 4/8 · 漂移 1 · 活动任务 1 · 最近写操作 32s 前完成 ───────────┐
├ 主表 ──────────────────────────────────────────────────────────────────────┤
│ Provider        on  up  oc  ocUserOwned  control  PID(全部)  端口   模型   │
│ CodeArts        ●   ○   ○   —            spawn    —          10087  —      │
│ WorkBuddy 国内  ●   ●   ●   —            spawn    21440      8787   31     │
├ 详情：on=开、up=停止、oc=未写入 → 下一步 [启动] [同步] [日志] ──────────────┤
└────────────────────────────────────────────────────────────────────────────┘
```

- 顶部指标：运行数、漂移数、活动任务数、最近写操作时间。
- 主区域：总览字段 + `control`、全部 `pids[]`、`ocUserOwned`、drift 明细列。
- 详情区：必须列出**具体组合**（如"开关=开、进程=停止、opencode=未写入"），而非只写"异常"。
- 可用操作：启动、停止、停止保留 opencode、重启、仅启用、关闭、同步、全部启用、全部关闭。
- 异常入口：失败任务输出、`error`、日志入口。
- 操作中状态：行内显示"正在启动/停止/切换"，**保留最近一次真实状态**并显示运行时长；任务结束后先重查再替换；动作成功但刷新失败显示"命令已完成，状态未确认"。
### 3.3 `quota` `/quota?provider=codearts`

```text
┌ 额度                                   [provider ▼] [全部|可查|不可用|需处理] ┐
│ 可查来源 7/9 · 额度覆盖 78% · 需处理提醒 2                                  │
├ Provider 卡片（1/2/3 列）──────────────────────────────────────────────────┤
│ Qoder 国内版  [正常]  服务在线        CodeArts Agent [需处理 1] 服务在线     │
│   ◕ 62%  剩余 496 / 800 credits       ◕ 99%  剩余 6599 / 6600 credits       │
│   重置 2026-12-01 · 21 天后            重置 2026-11-24 · 即将过期 99        │
│   账号 example-user · 数据 45s 前      账号 account-a/account-b              │
│   签到：可领取（尚未接入统一命令）      签到：活动未开放                      │
├ WorkBuddy 国内版（凭证天数，不并入 credits）─────────────────────────────────┤
│   凭证剩 29.0 天 · 到期 2026-12-24 00:00 UTC · 约 29 天                    │
└────────────────────────────────────────────────────────────────────────────┘
```

- 顶部指标：可查来源数、额度覆盖率、需处理提醒数；**不做跨家总额/排行榜**。
- 主区域：每家一张卡片（`ProviderChip`、服务状态、额度环形 gauge、剩余/总量/单位、重置日/倒计时、账号明细、签到 badge）；provider/状态筛选与排序（问题优先/名称/采集时间）。
- 无总量或剩余未知时画**虚线环**并明示「未提供总量」/「剩余未知」，不画假进度。
- `days`（WorkBuddy 凭证天数）独立成块，显示 UTC 到期日与倒计时，不并入 credits 汇总。
- 详情区：`reason`/`detail`/`error`/`fetchedAt`/`receivedAt`，避免把网关缓存时间当实时时间。
- 可用操作：刷新（可带 `refresh`）、筛选/排序、展开详情、跳账号页。签到按钮在统一命令接入前禁用并说明原因，**不发明 ActionName**。
- 异常入口：单家 `error` 行内标注 `不可用` + 原因；`available=false` 显示 `reason`。
### 3.4 `accounts` `/accounts?provider=trae-local`

图例：`*` 当前生效 · `+` 参与轮询 · `-` 已停用 · 空白 = 可切换但当前未生效。

```text
┌ Provider: trae-local · 可切换 · 3 个账号 · 数据 4m 前 ──────────────────────┐
│ *+ account-a   示例名A   health ok    当前生效                             │
│  + account-b   示例名B   health warn  参与轮询                             │
│  - account-c   示例名C   health error 已停用：detail 摘要                  │
├ 选中详情：dry-run → 切换到 account-b，将写配置并重启（未生效）─────────────┤
└────────────────────────────────────────────────────────────────────────────┘
```

- 顶部指标：provider 是否 `switchable`、账号数、生效账号、`health.level` 汇总。
- 主区域：`key`/脱敏 `name`/脱敏 `uid`/`enabled`/`active`/`detail`/`health`。
- 详情区：dry-run 结果，以及该 provider 是否支持恢复整池/添加账号/重新登录。
- 可用操作：预览切换（dry-run）、确认切换、恢复整池、添加账号、登录。Qoder 单账号只显示"换号请重新登录"，不显示普通槽位切换。
- 异常入口：`health.notes[]` 逐条列出，错误项给"重新登录"入口。
### 3.5 `logs` `/logs?provider=codearts&lines=500&filter=&follow=1`

```text
┌ 控制条 ────────────────────────────────────────────────────────────────────┐
│ provider ▼codearts · 行数 500 · ●跟随中 · 过滤 [      ] · 3 处匹配         │
│ 读取 1s 前 · 流式(SSE) · 截断：仅显示最近内容                              │
├ 日志正文（等宽、虚拟滚动、已剥离 ANSI/OSC 并脱敏）─────────────────────────┤
│ 21:04:11 [info] up on 10087                                                │
│ 21:04:12 [warn] quota low                                                  │
└────────────────────────────────────────────────────────────────────────────┘
```

- 顶部指标：`lastSuccessAt`（最近读取）、行数档位、跟随/暂停、匹配数、截断提示。
- 主区域：SSE 跟随；虚拟滚动只渲染可视窗口且保持滚动锚点；进程日志与**操作输出**用不同标签，不混成一条时间线。
- 详情区：日志来源说明（`GET /logs` 文本 vs `GET /logs/stream` SSE）、读取错误。
- 可用操作：暂停/继续、改过滤文本、增减行数档位、跳到末尾并恢复跟随、清空显示缓冲（不删磁盘日志）。
- 异常入口：读取失败时保留上一段文本并标 `stale`，给重试入口。
### 3.6 `diagnostics` `/diagnostics?provider=codearts`

四个分区，按顺序：环境（`GET /api/env`）→ 自检（`GET /api/doctor`，退出码 + 脱敏文本）→ 健康（`GET /api/health-check?probe=0`，文本）→ 真实试打（默认折叠）。

- 顶部指标：doctor 退出码、健康项通过数、上次检查时间、平台限制条数。
- 主区域：分区列表；`health.mjs --json` 落地前**展示清理后的文本**，不得用正则解析成结构化字段。
- 详情区：选中项的完整输出、可能费用提醒、平台不支持原因。
- 可用操作：运行 doctor、运行无试打健康检查、显式触发真实试打（加强确认）、重读环境。真实试打**从不自动**。
- 异常入口：非零退出码高亮，附"进入日志"链接并保留 `provider`。

- 顶部六张 KPI：会话/提示、会话步骤（带 steps sparkline）、Token 构成、上报成本、活跃/连续、工具成功率。
- 主区域：每日活动双模式面积图（steps 默认；tokens 仅在数据真带按日 Token 时可用）、Token 构成环形图、缓存读写堆叠条、工具成功率 gauge、缓存效率卡。
- `Token 构成 = input + output + reasoning`；缓存读写在环形图外单独展示，**不重复累计**。
- 模型表行内 steps 占比条，支持排序（`sort`/`dir` 进 URL）、详情抽屉与当前视图 CSV 导出（BOM + 转义）。
- 详情区：选中模型的完整 Token、缓存与 `cost`，并标明 `cost` 不折算积分。
- 可用操作：切换 `range`、刷新、排序、导出 CSV、跳 `gateway/usage` / `reports`。
- 异常入口：OpenCode 不可用或接口失败时本页显式错误，其他页继续工作；失败保留旧数据并标 `stale`。
- 口径红线：`steps` 永不显示为"请求数"；`cost=0` 是返回值，不解释为"没有消耗"；工具成功率不代替模型请求成功率。
### 3.8 `gateway` `/gateway/*`

```text
┌ 网关 8785 · ●可达 · 上游 9 家 · 冷却 1 · 粘性 2 ───────────────────────────┐
│ [调度] [用量] [降级链] [密钥] [免费供应商] [本地应答]                      │
├ Provider 调度 lane 卡片 ───────────────────────────────────────────────────┤
│ codearts [运行中]  OpenAI · :10087     trae-local [冷却中 30s] 双协议 :7863│
│ 权重 1.00 ▓▓▓▓▓▓▓▓  并发 0 ░░░░░░░░   权重 0.70 ▓▓▓▓▓░░░  并发 1 ▓▓░░░░░│
│ 成功率 99% ▓▓▓▓▓▓▓▓  额度比 82%       成功率 91% ▓▓▓▓▓░░░  额度比 55%     │
│ 连续失败 0 · 粘性 0                    连续失败 2 · 粘性 2                 │
└────────────────────────────────────────────────────────────────────────────┘
```

| 子路由 | 主区域 | 可用操作 | 异常入口 |
|---|---|---|---|
| `/gateway` | 调度 lane 卡片：`weight/inFlight/successRate/quotaRatio/consecutiveFails/cooldownKind/sticky`，冷却倒计时 | 刷新；清空模型缓存（`POST /v1/gateway/models/refresh`） | 冷却中的上游给"原因 + 剩余时间" |
| `/gateway/usage` | 六 KPI（请求/失败/错误率/输入/输出/平均耗时）+ 双轴请求/错误面积图 + 输入/输出 Token 堆叠图 + Provider/模型 Top 表 + 按天明细 | 切换范围、刷新 | 聚合为空与请求失败分别呈现 |
| `/gateway/combos` | 降级链（`combo:*`）改为阶梯链路，逐环标注就绪/离线/冷却/未知，展示成员顺序与并集模型 | 添加/删除链、刷新模型列表 | 链成员不可用时标注 |
| `/gateway/keys` | 密钥卡片/表格（仅前缀/状态，**无明文**），公开字段复制 | 新增/禁用/删除/重置用量 | 说明无效密钥仅 `strict` 下被拦 |
| `/gateway/free` | 18 家免费供应商只读清单（3 本机免账号 + 15 免费额度） | 只读；**不参与 `on/off`** | 逐家不可用原因 |
| `/gateway/local-answers` | 本地应答开关组（quota/prefix/title/suggestion/filepath/all） | 逐项开关（普通写，需确认） | 冲突或未生效时给命令回显 |

- 顶部指标：网关 `up`、上游在线数、冷却中数量、粘性命中数。网关是**叠加层**，`on == up`，无独立开关；调度 lane 卡片只读，页头仅保留刷新与「清空模型缓存」（写操作需确认）。
- 详情区：选中上游的 `dialect/port/cooldownKind` 与最近失败摘要。
- 异常入口：`/health` 探活失败、上游全冷却、密钥无效三类独立提示，不合并成"网关故障"。
- 口径：网关用量是 `requests/errors/inputTokens/outputTokens`，与 `/usage` 的 steps 不换算、不相加。
### 3.9 `settings` `/settings`

- 顶部指标：当前主题、刷新间隔摘要、只读/演示状态、桥接版本与端口。
- 主区域：主题（dark/light/system）、刷新间隔覆盖（对齐 [00 §8](00-design-baseline.md) 默认值）、只读模式、演示模式、桥接连接信息、默认 `range`。
- 详情区：每个开关的作用范围与影响；只读/演示由桥接层拦截，UI 说明"将在服务端被拒绝"。
- 可用操作：切换主题三态、调整刷新间隔、切换只读/演示（需确认，演示模式会断开真实数据）；高对比在顶栏主题菜单切换。
- 异常入口：桥接不可达时本页仍可查看，但写开关禁用并注明原因。
### 3.10 `reports` `/reports`

```text
┌ 报表  [24h] [7d*] [30d] [全部]  [刷新全部]  [CSV 明细] [JSON 汇总] [打印] ┐
│ 报告摘要：范围 7d · 生成时间 … · 网关窗口近 7 天                           │
│ 数据源：OpenCode 用量 正常 · 额度 正常 · Provider 正常 · 网关用量 旧数据… │
│ 结论：仅在对应数据源有数据时生成（告警/空白/可领取/漂移）                  │
├ KPI：会话/步骤 · Token · 成本 · 活跃/连续 · 工具成功率 · 额度覆盖 ─────────┤
├ 趋势：按天 Tokens + Provider Top ──────┬ 模型 Top + 网关快照 ──────────────┤
├ Provider 状态矩阵 ────────────────────┬ 额度告警 + WorkBuddy 凭证天数 ─────┤
└ 页脚：导出说明（CSV 明细 / JSON 汇总，浏览器内生成，不上传）───────────────┘
```

- 数据源只有五个现有只读查询：`useUsage`、`useQuota`、`useProviders`、`useGatewayUsage`、`useGatewayStatus`；**未改后端**。
- 摘要逐源标注 `正常/旧数据/失败/加载中/空`；空 = 查询成功但没有数据，不等于 0。
- 范围映射：`24h→网关 1 天`、`7d→7`、`30d→30`、`all→90`（网桥按自然日分片上限 90 天，页面明示）。
- 导出：CSV 含 KPI、按日、Provider、模型、网关按天/Provider、额度桶与 Provider 状态；JSON 为结构化汇总。两者均在浏览器 Blob 生成。
- 页面内联 `@media print` 打印样式：白底、去阴影、区块 `break-inside: avoid`；导出/范围按钮 `print:hidden`。
- 口径红线与 `/usage`、`/quota`、`/gateway/usage` 相同：steps ≠ HTTP 请求，cost ≠ 积分余额，不跨厂商求和。

## 4. 状态与漂移
### 4.1 四个独立状态 + 漂移

`on`（开关）、`up`（进程/端口）、`oc`（客户端配置）、`auth`（认证）互不推导，各自一个徽标；`drift` 由后端字段派生，UI **不猜**。

| drift | 判定 | 文案 | 下一步 |
|---|---|---|---|
| `stopped` | `on=true, up=false` | 开关=开、进程=停止 | 启动 / 查看日志 |
| `notSynced` | `on=true, oc=false && !ocUserOwned` | opencode 未写入 | 同步 |
| `stillRunning` | `on=false, up=true` | 开关=关、进程仍在运行 | 停止 |
| `ocUserOwned` | `ocUserOwned=true` | opencode 由用户自管 | 不报同步漂移 |

`auth.state ∈ {valid,expiring,expired,missing,unknown}`；`unknown` 不得渲染为"正常"。
### 4.2 徽标、数值、额度与日志交互

- 每个状态 = **图标 + 文字 + 数值**三者同时存在，颜色只是辅助（WCAG 2.1 AA 对比度）。
- `up=true` 不代表凭证有效，凭证有效不代表 `oc=true`，`oc=true` 不代表请求会成功——三段提示常驻帮助页。
- `models: null` 渲染 `—`，`models: 0` 渲染 `0`；`null`/加载失败/未查询/真实 `0` 是四种不同状态。
- 额度环形 gauge 仅在 `total > 0` 且 `remaining` 有效时画实线弧；否则画虚线环并写「未提供总量/剩余未知」，不留空条；数值用后端有意义的小数位，`unit` 原样展示。
- `days` 单位行不画百分比环，只显示"凭证剩 N 天 · 到期 UTC 时间"；色带只作辅助，数值与单位始终存在，`expiring` 附文字提醒。
- 实时状态用 `LiveBadge`：网关可达/不可达/未知、只读、演示；图标 + 文本 + 颜色三通道，圆点只是装饰。
- 日志交互：跟随（`follow=1`，SSE 推流）/ 暂停（手动向上滚动自动暂停并保留阅读位置）/ 过滤（只作用当前已加载文本，不宣称搜索完整历史）/ 虚拟滚动（只渲染可视窗口，滚动锚点不跳动）。
- Provider 稳定分类色：`codearts` 紫 · `qoder-cn` 青 · `qoder` 蓝 · `trae-local` 绿 · `workbuddy` 黄 · `workbuddy-global` 浅紫 · `zcode` 橙 · `loomy` 洋红 · `raccoon` 红 · `gateway` 中性。图表与徽标共用同一映射，不用颜色单独表意。
### 4.3 任务进度与"命令完成但状态未确认"

```text
任务 1 运行中 · restart workbuddy · 4.2s
├─ 状态：running（不预改目标状态）
├─ 输出：最近 2000 行（超出时前移并提示截断）
└─ 刷新：refreshStatus=pending → 完成后 confirmed / failed
```

`Task.status ∈ {queued,running,succeeded,failed,cancelled}`，`refreshStatus ∈ {pending,confirmed,failed,notRequired}`。写任务**全局串行**，同目标重复提交去重；`refreshStatus=failed` 时显示"命令已完成，状态未确认"，绝不渲染为已验证成功。
## 5. 交互
### 5.1 确认框（普通 / 高风险）

```text
普通（危险等级 normal：up/down/keep-oc/restart/off/sync）
┌ 确认重启？ target=workbuddy（WorkBuddy 国内版）──┐
│ 影响：停止并重启该反代，随后同步客户端配置      │
│ 命令：node router.mjs restart workbuddy         │
│                       [取消(默认焦点)] [确认]   │
└─────────────────────────────────────────────────┘
高风险（危险等级 high：on / all / none / 恢复整池）
┌ 仅启用 codearts —— 会影响多个 provider ─────────┐
│ 将启用：codearts                                │
│ 将关闭并停止（8 家）：qoder-cn qoder trae-local │
│   workbuddy workbuddy-global zcode loomy raccoon│
│                       [取消(默认焦点)] [执行]   │
└─────────────────────────────────────────────────┘
```

- 高风险**必须列出受影响名单**，默认焦点"取消"，不能用普通 `Enter` 绕过阅读，不使用易误触的单键确认。
- 命令文本用于透明说明，**不可编辑成任意命令**；不提供 Shell 输入框。
- `read-only` 模式在桥接层阻断写；UI 打开"当前为只读模式"说明，而不是隐藏按钮。
### 5.2 账号切换（dry-run → 确认 → 切换）

```text
dry-run ✓ 切换到 account-b（trae-local）
将写入：账号 B 配置 · 将重启：是 · 当前生效：account-a · [取消] [确认切换]
```

1. 选择账号 → 预览切换（`account <id> <key> --dry-run --json`）。2. 详情区展示目标账号、当前生效项、是否重启、配置影响。3. 确认框（normal）确认正式切换（`account <id> <key> --json`）。4. 完成后**重新查询**账号、provider、额度，不乐观更新 `active`。
### 5.3 登录 / 添加账号：等待外部终端

```text
┌ 等待外部登录完成 ─────────────────────────────────┐
│ 已在原生终端启动：node router.mjs login codearts  │
│ 请在终端完成扫码/输入，本页不接收你的输入         │
│ 状态：等待中 · 已等待 42s    [取消等待]           │
│ 完成后本页自动刷新账号与认证状态                  │
└───────────────────────────────────────────────────┘
```

- 浏览器**不能**接管 `stdin`：桥接只**发起并等待**，不转发输入，也不采集输出中的敏感内容。
- 不自动登录：后台执行 `up/on/all/restart` **必须**带 `--no-login`，禁止自动打开浏览器。
- 取消只结束 UI 等待，不保证终止终端进程，需明确说明。
### 5.4 命令面板（⌘K / Ctrl+K）

```text
┌ 命令 ─────────────────────────────────────────────┐
│ > codea                                           │
│ 跳转   服务 · codearts                            │
│ 跳转   日志 · codearts                            │
│ 动作   启动 codearts                  （普通写）  │
```

## 7. 加载 / 空 / 错误 / stale / 只读 / demo 文案表

| 场景 | 文案 | 行为 |
|---|---|---|
| 首次加载 | `正在读取 provider 状态…` | 骨架屏，其他页签仍可切换 |
| 合法空账号 | `该 provider 当前没有账号` | 附登录说明入口 |
| 合法空额度桶 | `没有可展示的额度桶` | 不等于查询失败 |
| 未查询 / 字段缺失 | `—` | 与 `null`、真实 `0`、失败分别呈现，不整页反序列化失败；网关未运行与未查询分别标注 |
| 单家失败 | 行内 `不可用` | 详情显示 `error.code/message/retryable`；OpenCode 不可用时仅用量页报错，其他页继续工作 |
| 全局桥接失败 | `桥接不可达，正在显示缓存数据` | 保留导航与旧值，给排查建议 |
| 旧数据刷新失败 | `stale · 最后成功 45s 前` | 保留旧值，不覆盖为 0 |
| 命令完成未确认 | `命令已完成，状态未确认` | 不用目标状态渲染 |
| 只读模式 | `当前为只读模式，写操作已在桥接层禁用` | 页面可浏览 |
| 演示模式 | `DEMO · 数据为匿名虚构值` | 顶栏常驻徽标；不 spawn 进程、不读真实文件 |
| 平台不支持 | `当前平台不可用` + 具体原因 | 禁用操作，不静默隐藏 |
| 内容截断 | `仅显示最近内容` | 日志/任务输出超出上限时 |
## 8. 禁止的交互

1. **不预改状态为成功**：按钮按下后不把行渲染成目标状态，`pending` 期间保留最近一次真实值。
2. **不用颜色单独表意**：状态必须有文字/图标/数值，错误不只显示红色。
3. **不在后台自动登录/签到/试打/重启**：`login`、签到、真实试打一律显式触发；`up/on/all/restart` 必带 `--no-login`。
4. 不用单个开关隐藏 `on` 的排他语义（"仅启用"必须走高风险确认并列出被关闭名单）。
5. 不把 `steps` 显示为请求数，不把 `cost` 折算为积分，不做跨家总额/排行榜，不把 `days` 与 `credits` 汇总成同一单位。
6. 不让新日志/新事件打断用户正在查看的历史位置（暂停点保留）。
7. 不在弹窗中提供任意命令编辑框或 Shell 输入；不改写 `router.mjs`、`gateway/`、`tui/` 的既有语义。
8. 不在 URL、日志、任务输出中出现 token、PAT、完整 cookie、绝对路径等敏感值；不靠前端隐藏实现只读/演示约束——必须由桥接层拦截。

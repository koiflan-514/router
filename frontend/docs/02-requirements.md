# 02 产品需求

状态：设计基线  
适用范围：网页面板 MVP 与明确的后续方向  
对应需求：本文件（FR-101–199、NFR-101–110）  
唯一事实来源：[00 设计基线](00-design-baseline.md)；口径与 [`tui/docs/02-requirements.md`](../../tui/docs/02-requirements.md) 一致，媒介不同。

## 1. 背景

八家本机反代已由根目录 `router.mjs` 管起来，统一网关（`gateway/`）也已能把它们拼成一个端口。
但日常运维仍分散在 `list`、`account`、`credits`、`health`、`logs`、`gateway status` 和十来条启停
命令里；同一时刻的状态要靠人脑拼接，出错时定位路径很长。

`frontend/` 要做的是**浏览器控制台**：本地运行、可读可控、出错能定位。它必须回答：

- 八家现在能不能用：开关、进程、opencode 配置、凭证四个状态各是什么，哪里漂移了？
- 谁在跑，怎么启停/重启/开关/同步，操作的影响面有多大？
- 余额、凭证天数、签到、重置日分别是什么，数据是什么时候取的？
- 当前生效哪个账号，怎么切换、怎么恢复整池，哪些家不支持切换？
- 某家为什么报错，doctor 与健康检查怎么说？
- 网关调度、降级链、密钥、免费供应商、本地应答现在是什么样？

约束（来自 00 设计基线，不可协商）：

| 约束 | 含义 |
|---|---|
| 浏览器不直连网关 | 网关无 CORS 且不能启停进程；**所有数据与写操作一律经桥接服务**（`frontend/server/`） |
| 桥接只监听回环 | `127.0.0.1:8792`；非回环来源一律拒绝 |
| 网关是叠加层 | `gateway` 条目 `on == up`，**不参与 `on/off`**，UI 不给它开关 |
| 写操作全局串行 | 任一时刻只允许一个写任务在跑，其余排队，同目标去重 |
| 危险操作默认取消 | 确认弹窗默认焦点在"取消"，高风险先列受影响名单 |
| 只读/演示在桥接层拦截 | 前端隐藏按钮不是安全边界 |

## 2. 目标用户

### 2.1 主要用户

本机 router 的维护者：同时管理多个 AI 编程订阅与反代，熟悉基本命令行，希望**少敲命令、
多看清状态**。使用场景是"开一个标签页盯着"，要求刷新便宜、状态不骗人、危险操作拦得住。

### 2.2 次要用户

- **没有凭证的开发者**：需要在无凭证机器上看清整个界面（用 `--demo` 匿名 fixtures）。
- **单家排障者**：只关心某一家为什么挂，需要从汇总一步跳到日志/诊断。
- **演示者**：向他人展示面板能力，不希望触碰真实进程与凭证。

MVP 是**单机单用户**工具，不为团队管理员、审计员、远程租户设计。

## 4. 范围

### 4.1 MVP 必须包含

- 九个页签：总览、服务、额度、账号、日志、诊断、用量、网关、设置（含 `gateway/*` 嵌套路由）。
- 八家 provider + `gateway` 条目的真实只读状态，四个状态维度独立呈现。
- 额度、账号、日志、诊断、用量、网关的只读视图，均带数据时间与 stale 标识。
- 单 provider 与服务集合的写操作：`up/down/restart/on/off/all/none/sync/down --keep-oc`。
- 账号查看、切换 dry-run、正式切换、恢复整池；交互式登录只发起不接管 stdin。
- 日志尾部 + SSE 跟随、过滤、暂停、有界缓冲与脱敏。
- doctor、无试打健康检查；真实试打显式触发、加强确认、默认折叠。
- 网关调度/用量/balance/combos/keys/免费供应商/本地应答的只读展示，模型缓存刷新。
- `--demo` 演示模式与 `--read-only` 只读模式，**由桥接层强制**。
- 危险操作确认（默认取消）、写任务全局串行、任务输出可查看、退出/刷新保护。
- Windows/Linux 上的构建与自动化测试；无凭证 CI 可跑通。

### 4.2 后续可以考虑

- 网关 `combo` / `key` 的写操作（新增、删除、禁用、重置用量）与密钥生命周期管理。
- 结构化健康输出（后端 `--json` 落地后，见 00 §13 增量提案）。
- 配置导出、诊断报告、匿名支持包。
- 请求级 TTFT/P75、逐请求日志、路由尝试追踪。
- 多语言完整覆盖（英文化全部文案与图表标签）。
- 远程主机后端——但必须先有认证、授权与传输安全设计。

### 4.3 明确不做

- 多用户、RBAC、团队计费、虚拟 Key 管理与租户隔离。
- 远程主机后端（MVP 只服务本机回环）。
- 任意 Shell 输入、任意命令执行、可编辑的"自定义命令"框。
- 采集提示词、响应正文或用户身份信息。
- 跨厂商积分汇总、排行榜、统一资产估值。
- 替代 `router.mjs` 的进程树清理算法；直接改写各厂商凭证文件。
- 自动签到、自动试打、自动重启循环、自动登录。
- 修改 `router.mjs`、`gateway/`、`tui/` 的既有语义；需要新字段时走增量兼容提案。

### 5.1 总览与状态（FR-101–109）

| ID | 需求 | 验收摘要 |
|---|---|---|
| FR-101 | 必须列出桥接返回的全部 provider（含 `gateway` 条目） | 八家 + 网关均出现；新增 provider 不需要新增页面 |
| FR-102 | 必须分别显示启用开关、进程、opencode 配置、认证四个状态 | 不用单个"正常"覆盖；四态可独立判读 |
| FR-103 | 必须显示端口、PID(s)、模型数与数据时间 | `models=null` 显示 `—`，不得当成 0 |
| FR-104 | 必须显示 `drift` 明细（`stopped`/`notSynced`/`stillRunning`） | 漂移由后端字段推导，UI 不猜；`ocUserOwned` 不报同步漂移 |
| FR-105 | 必须汇总运行数、认证异常、漂移数与可处理提醒 | 汇总可由明细逐项推导，不出现无法解释的数字 |
| FR-106 | 必须能从选中 provider 跳到服务、日志或诊断 | 跳转保留当前 provider 焦点（进 search params） |
| FR-107 | 必须显示各数据源最后成功时间与 `stale` | 单家查询失败不得清空其他 provider |
| FR-108 | 应该支持按状态/关键词筛选与按列排序 | 筛选与排序进 URL，刷新与回退后保持 |
| FR-109 | 应该把 `gateway` 明确标为叠加层 | 说明 `on == up` 且不适用 `on/off`，不显示网关开关控件 |

### 5.2 服务控制（FR-110–119）

| ID | 需求 | 验收摘要 |
|---|---|---|
| FR-110 | 必须支持 `up/down/restart` | 一律参数数组 spawn，禁止 `sh -c`/`cmd /c` 拼接 |
| FR-111 | 必须支持 `on/off/all/none/sync` | 文案准确描述开关与进程副作用，不只写"成功" |
| FR-112 | 必须支持 `down <id> --keep-oc` 且与普通停止区分 | 确认文案明示"保留 opencode provider" |
| FR-113 | 所有副作用操作必须确认，默认焦点为"取消" | 高风险（`on/all/none`、恢复整池）先列受影响名单 |
| FR-114 | 写操作必须全局串行 | 任一时刻只有一个写任务运行，其余进入队列 |
| FR-115 | 必须对同目标重复提交去重 | 连按不会重复启动/切换 |
| FR-116 | 必须显示任务状态与有界输出（stdout/stderr） | `queued/running/succeeded/failed/cancelled` 可区分，输出可展开 |
| FR-117 | 操作完成后必须重新查询真实状态 | 仅在 `refreshStatus=confirmed` 后更新 UI，不凭退出码臆断 |
| FR-118 | 后台启动动作必须带 `--no-login` | 面板不得自动打开浏览器或触发登录 |
| FR-119 | 应该提供活动任务列表与取消入口 | 取消后状态为 `cancelled` 并重新查询 |

### 5.3 额度（FR-120–129）

| ID | 需求 | 验收摘要 |
|---|---|---|
| FR-120 | 必须按 provider/账号展示余额、总量、单位与重置信息 | 缺失字段显示 `—`，不显示 0 |
| FR-121 | 必须显示来源可用性与失败原因 | 未登录、服务未运行、接口失败可区分 |
| FR-122 | 必须显示 `fetchedAt` 与 `stale` | 旧数据不得冒充实时结果 |
| FR-123 | 必须区分 `credits` 与 `days` 两种单位 | WorkBuddy 凭证天数不并入积分汇总 |
| FR-124 | 签到入口必须由后端能力决定 | 不支持时说明原因，不显示可点击假象 |
| FR-125 | 签到必须显式确认，刷新绝不触发签到 | 确认框默认取消；`refresh` 只重取数据 |
| FR-126 | 即将到期与额度耗尽必须醒目提示 | 不只依赖颜色，同时给文字与图标 |
| FR-127 | 应该如实显示 access/refresh 到期日相同的账号 | 不去重制造"缺少数据"的假象 |
| FR-128 | 应该支持单家刷新与"仅看异常"筛选 | 刷新带 `?refresh` 并更新 `fetchedAt` |
| FR-129 | 应该标注额度数据来自网关 `balance` 还是 CLI 回退 | 展示来源，便于判断可信度与时效 |

### 5.4 账号与登录（FR-130–139）

| ID | 需求 | 验收摘要 |
|---|---|---|
| FR-130 | 必须显示当前生效、参与轮询、停用与可切换状态 | 有图例说明符号含义 |
| FR-131 | 切换前必须支持 dry-run 预览 | 显示目标账号与影响，不写入任何文件 |
| FR-132 | 正式切换必须使用现有 `account` 命令 | 面板不直接复制或修改凭证文件 |
| FR-133 | 恢复整池必须限定到选定 provider | 不影响其他 provider |
| FR-134 | 交互式登录/加账号只发起并等待 | 显示"等待外部登录完成"，可取消，不接管 stdin |
| FR-135 | 单账号与多账号交互必须不同 | 不可切换的家不显示普通槽位切换 |
| FR-136 | 必须显示 `health.level` 与 `notes` | 结构化字段优先，不靠正则解析文本推断 |
| FR-137 | 应该展示账号体检结果与修复命令文本 | 只展示命令，不在面板内执行任意命令 |
| FR-138 | 应该用稳定标识引用账号（`key`/`uid`） | 绝不展示凭证明文 |
| FR-139 | 应该对单凭证家明确说明"不适用切换"及原因 | 给出原因文案，而非只放禁用灰按钮 |

### 5.5 日志与诊断（FR-140–149）

| ID | 需求 | 验收摘要 |
|---|---|---|
| FR-140 | 必须能选择 provider 与日志尾部行数 | 使用现有 `logs <id> <lines>` 能力 |
| FR-141 | 必须支持跟随（SSE）、暂停与过滤 | 页面不可见时停止推流，可见时立即补一次 |
| FR-142 | 日志缓冲必须有上限 | 默认 ≤2000 行，长时间运行不无限增长 |
| FR-143 | 渲染前必须剥离 ANSI/OSC 并脱敏常见密钥 | 防转义注入与意外泄密 |
| FR-144 | 必须支持 `doctor` 与无试打健康检查 | 不消耗模型额度 |
| FR-145 | 真实试打必须显式触发并加强确认 | 从不自动执行；明示可能消耗额度与等待时间 |
| FR-146 | 健康失败必须保留具体错误 | 不仅显示红灯，给出下一步 |
| FR-147 | doctor/健康文本可展示，但不得正则解析成结构化字段 | 遵守 00 §13 的增量提案纪律 |
| FR-148 | 应该支持关键词高亮与脱敏后的日志复制/下载 | 下载内容同样先脱敏 |
| FR-149 | 应该支持从错误提示一键跳转到对应日志或诊断 | 保留 provider 与时间点上下文 |

### 5.6 用量分析（FR-160–169）

| ID | 需求 | 验收摘要 |
|---|---|---|
| FR-160 | 必须使用 OpenCode 官方统计接口 | 不读数据库、不伪造请求数据 |
| FR-161 | 必须区分 `steps` 与 HTTP 请求数 | 界面与帮助明确 `steps` ≠ 请求数 |
| FR-162 | 必须展示会话/提示、Token 构成、缓存、工具成功率与模型聚合 | 每个数值可从官方 stats 字段直接验证 |
| FR-163 | 必须支持 24h/7d/30d/全部并显示当前范围 | 范围进 search params，URL 可分享 |
| FR-164 | 必须有每日活动与模型详情，无数据时显示空状态 | 无数据不生成随机曲线 |
| FR-165 | 必须标明 `cost` 是 OpenCode 上报值 | 不折算积分、不推断实际扣费 |
| FR-166 | 用量接口失败不得影响服务管理 | 保留旧数据并标 `stale`，其他页仍可用 |
| FR-167 | 应该为 provider 使用稳定分类色 | 与 00 §10 的 provider 色映射一致 |
| FR-168 | 应该为图表提供表格视图或文本等价 | 关键数值不只存在于图形中 |
| FR-169 | 应该允许复制/导出当前范围聚合 | 导出内容不含提示词与响应正文 |

### 5.7 网关（FR-170–179）

| ID | 需求 | 验收摘要 |
|---|---|---|
| FR-170 | 必须说明网关是叠加层、不参与 `on/off` | 网关条目 `on == up`；无开关控件，只有进程状态 |
| FR-171 | 必须展示调度快照 `/v1/gateway/status` | 权重、冷却、并发、成功率、粘性均可见 |
| FR-172 | 必须展示网关用量与 `/v1/gateway/balance` | 经桥接转发，展示数据时间 |
| FR-173 | 必须只读展示 `combo` 列表 | 显示降级链顺序与成员模型 |
| FR-174 | 必须只读展示 gateway keys 元数据 | 仅名称/状态/用量；密钥库只有 SHA-256，绝不见明文 |
| FR-175 | 必须只读展示 18 家免费供应商清单 | 标注"由网关直接当上游"，不参与 `on/off` |
| FR-176 | 必须展示本地应答（local answers）开关状态 | 展示五个固定问题类别的启用情况 |

### 5.8 设置 / 主题 / 可访问性 / 国际化（FR-180–189）

| ID | 需求 | 验收摘要 |
|---|---|---|
| FR-180 | 必须提供 dark/light/system 主题 | 默认 dark；选择持久化，不闪烁 |
| FR-181 | 必须可配置刷新间隔并显示当前值 | 覆盖 00 §8 默认值；非法值回退默认 |
| FR-182 | 必须提供只读模式 | 由桥接层阻断写，不只是隐藏按钮 |
| FR-183 | 必须常驻显示工作范围（local/demo） | 顶栏可见，切换模式需显式确认 |

| FR-189 | 应该统一数值与时间格式 | 端口/PID/日志等宽，数字右对齐，时间显示时区 |

### 5.9 通用交互（FR-190–199）

| ID | 需求 | 验收摘要 |
|---|---|---|
| FR-190 | 必须提供统一的加载、空、错误与部分失败状态 | 用户始终知道当前状态与下一步 |
| FR-191 | 必须提示错误可重试性与定位入口 | 失败处给出重试按钮与日志/诊断链接 |
| FR-192 | 必须把选中 provider、范围、过滤、排序放进 URL | 可分享；浏览器前进/后退有效 |
| FR-193 | 必须支持在无凭证机器上跑通全部页面 | `--demo` 匿名 fixtures，不 spawn 进程、不访问真实文件 |
| FR-194 | 演示与只读模式必须在桥接层拦截 | 前端隐藏不作为安全边界；演示数据必须是虚构值 |
| FR-195 | 必须对命令输出与日志统一脱敏 | 剥离控制序列；JSON/任务输出中不出现 token 或明文密钥 |
| FR-196 | 必须显示写队列状态 | 顶栏常驻活动任务数与串行提示 |
| FR-197 | 应该提供命令面板 | 可跳页，可对已授权目标发起写操作并走同一确认流程 |
| FR-198 | 应该保持窄屏可用 | 抽屉侧栏 + 响应式表格，关键操作在窄屏仍可完成 |
| FR-199 | 应该保证刷新/多标签一致性 | 只读状态自动收敛；写操作一律以服务端队列为准 |

## 6. 非功能需求（NFR-101–110）

| ID | 类别 | 要求（必须） |
|---|---|---|
| NFR-101 | 平台 | Windows/Linux 均可运行与构建；桥接只监听 `127.0.0.1:8792`；支持主流 Chromium 系浏览器 |
| NFR-102 | 响应 | 数据获取与界面交互解耦；后台请求期间页面仍可操作，首屏可交互 |
| NFR-103 | 负载 | 同 key 请求去重；慢响应不触发请求堆积；`document.hidden` 时暂停轮询与 SSE |
| NFR-104 | 资源 | 日志与任务输出有界（默认 ≤2000 行）；不后台运行真实试打或签到 |
| NFR-105 | 安全 | 参数数组 spawn、写操作白名单、危险确认默认取消、写任务全局串行、只读/演示在桥接层拦截 |
| NFR-106 | 隐私 | 不上传遥测；不持久化凭证；fixtures 与文档样例全部为匿名虚构值 |

| NFR-110 | 可发布 | 构建可重复；产物不含凭证、日志、PID 文件或本机绝对路径 |

## 7. 额度与单位规则

| 规则 | 内容 |
|---|---|
| R1 | `credits` 只表示对应厂商返回的计数单位，不隐含人民币/美元，也不存在跨厂商兑换关系 |
| R2 | 可以在单账号内计算 `remaining / total`；总量缺失或 ≤0 时不显示百分比 |
| R3 | **不做**八家积分总和、跨厂商排行榜或统一资产估值（W-06） |
| R4 | `remaining = 0` 只表示接口返回 0，不自动推断所有模型不可调用；上游有说明则保留说明 |
| R5 | `expiring` 与 `remaining` 分开显示；重置日与到期日不得混用 |
| R6 | WorkBuddy 的"额度"是 access/refresh 有效天数，必须显示为凭证有效期 + UTC 绝对到期时间 + 服务在线；**不并入积分汇总**，也不以"不支持签到"代替额度状态 |
| R7 | 签到状态至少区分：已签到、可领取、活动未开放、接口不支持、账号禁用、未知 |
| R8 | 数据来源优先级：网关 `balance` 优先，缺失回退 CLI；回退必须在 UI 标注来源 |

## 8. 状态显示规则

| 规则 | 内容 |
|---|---|
| S1 | `null`、请求失败、尚未查询、真实 `0` 是**四种**不同状态；未知统一显示 `—` |
| S2 | 请求失败可保留上一份成功数据，但必须标 `stale` 并显示 `lastSuccessAt` |
| S3 | `models: null` 表示未查询或进程未运行，不得显示"0 模型" |
| S4 | 认证以结构化 `auth.state` 为准，不靠匹配中文 label 推断过期 |
| S5 | `drift` 由后端字段推导：`on=true,up=false→stopped`；`on=true,oc=false && !ocUserOwned→notSynced`；`on=false,up=true→stillRunning`；`ocUserOwned` 永不报同步漂移 |
| S6 | 四个状态互不蕴含：`up`≠凭证有效，凭证有效≠`oc=true`，`oc=true`≠请求会成功 |
| S7 | `gateway` 条目的 `on` 直接等于 `up`（叠加层），UI 不得为其渲染开关 |
| S8 | `stale` 仅在"有旧数据且最近刷新失败或超阈值"时置位；`stale` 必须同时给出最后成功时间 |
| S9 | `steps` 永远不等于 HTTP 请求数；`cost` 是 OpenCode 上报值，不折算积分 |

## 9. MVP 完成定义

MVP 只有同时满足以下条件才算完成：

1. `FR-101`–`FR-199` 均已实现，或经明确批准的范围调整并记录在 `10-implementation-plan.md`。
2. `NFR-101`–`NFR-110` 均有对应测试或人工验收记录（见 `09-testing.md`）。
3. 无凭证 CI 通过：`--demo` 可跑通九个页签、空/错/加载态齐全，且不 spawn 进程、不访问真实文件。
4. 只读模式与演示模式在**桥接层**被验证拦截：绕过前端直接调 `POST /api/actions` 仍被拒。
5. 写操作全局串行与去重有可复现测试；危险确认默认焦点在"取消"。
6. 状态口径有单一实现来源，`null ≠ 0`、`drift` 推导、`stale` 三类场景均有用例。
7. 网关只读展示不引入 `on/off` 语义；`gateway` 条目无开关控件。
8. 未采集提示词/响应正文/身份信息；样例与 fixtures 全部为匿名虚构值。
9. 文档、界面文案与实际命令语义一致；术语与 `tui/docs/12-glossary.md` 不冲突。
10. 发布物能清晰报告：Node/router 缺失、桥接不可达、网关不可达、单家失败与全局失败。

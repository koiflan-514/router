# 06 操作手册

状态：设计基线  
目标：让每个 TUI 动作与现有 CLI 的真实副作用一一对应

## 1. 操作分级

| 级别 | 类型 | 示例 | 默认行为 |
|---|---|---|---|
| L0 | 本地只读 | 切页、滚动、帮助、过滤 | 直接执行 |
| L1 | 后端只读 | 状态、账号、额度、日志、无试打健康 | 可手动或按策略刷新 |
| L2 | 普通写操作 | 启动、停止、重启、关闭、同步 | 弹窗确认，默认取消 |
| L3 | 多目标或高风险写操作 | 仅启用、全部启用、全部关闭、恢复整池 | 加强确认并列出全部影响 |
| L4 | 交互或消耗型操作 | 登录、添加账号、签到、真实试打 | 单独确认；挂起终端或明确消耗提醒 |

`--read-only` 下只允许 L0/L1。`--demo` 只操作 FixtureBackend 的模拟状态，不调用真实 CLI。

## 2. 三类状态必须先理解

- **开关 `on`**：用户希望启用哪些 provider。
- **进程 `up`**：反代当前是否运行。
- **客户端 `oc`**：provider 是否出现在 opencode 配置中。

它们可以合法地不一致。TUI 的操作文案必须分别描述改变哪一类状态，不能都称为“开启/关闭”。

## 3. 服务动作映射

### 3.1 启动 `u`

命令：

```bash
node router.mjs up <id> --no-login
```

语义：

- 启动指定 provider，不改变启用开关。
- 会按现有逻辑同步相关 opencode provider。
- 缺少凭证时只报告需要登录，不在后台隐式打开浏览器。

确认文案：目标 provider、端口、是否同步客户端。完成后刷新 list 和健康相关信息。

### 3.2 停止 `d`

命令：

```bash
node router.mjs down <id>
```

语义：

- 停止指定 provider。
- 默认从 opencode 同步移除该 provider。
- 不因此把 `router.json` 的启用开关改成关，因此之后可能出现“开关开、进程停”的有意状态。

确认框必须同时说明“停止进程”和“移除客户端 provider”。

### 3.3 停止但保留客户端 `K`

命令：

```bash
node router.mjs down <id> --keep-oc
```

只停止进程并保留 opencode provider。适用于临时释放资源；客户端仍可能选择一个当前不可用的 provider，详情中应提示这一点。

### 3.4 重启 `R`

命令：

```bash
node router.mjs restart <id> --no-login
```

停止并启动指定 provider，再按现有逻辑同步客户端。重启期间短暂不可用，不能在按钮按下时立即显示成功。

### 3.5 仅启用此家 `o`

命令：

```bash
node router.mjs on <id> --no-login
```

**这是排他操作，不是“把这一项也打开”：**

- 目标 provider 变为启用。
- 其他 provider 从启用集合移除。
- 其他正在运行的 provider 会被停止。
- opencode 配置同步为新的选择。

确认框必须列出其他将被关闭的 provider，风险级别 L3。

### 3.6 关闭此家 `x`

命令：

```bash
node router.mjs off <id>
```

从启用集合移除指定 provider，停止它并同步 opencode；其他 provider 保持原选择。

### 3.7 全部启用 `A`

命令：

```bash
node router.mjs all --no-login
```

启用并启动全部八家，再同步 opencode。可能显著增加内存和端口占用，也可能暴露多家凭证问题。确认框列出数量和缺失凭证提醒，L3。

### 3.8 全部关闭 `N`

命令：

```bash
node router.mjs none
```

停止全部 provider，清空启用集合并同步移除对应 opencode provider。不是简单“只停进程”。确认框必须列出全部影响，L3。

### 3.9 同步 `s`

命令：

```bash
node router.mjs sync
```

按当前启用集合同步 opencode。用户自管 `.jsonc` 的限制必须保留在后端输出中，TUI 不绕过限制直接编辑。

## 4. 账号操作

### 4.1 预览切换 `v`

```bash
node router.mjs account <provider> <account-key> --dry-run --json
```

- 不写账号池、不复制生效凭证、不重启。
- 使用后端返回的匹配结果，不由 Rust 猜账号序号。
- 预览结果与正式操作通过 provider、account key 和预览代次关联；账号列表变化后必须重新预览。

### 4.2 正式切换 `c`

```bash
node router.mjs account <provider> <account-key> --json
```

可能副作用：

- 修改当前生效账号或多账号启用集合；
- 写入对应凭证或状态；
- 重启正在运行的 provider；
- 改变后续额度与可用模型。

完成后刷新账号、provider 和额度。成功文案不能只写“完成”，应显示最新生效账号或后端返回的启用集合。

### 4.3 恢复整池 `a`

```bash
node router.mjs account <provider> --all --json
```

只作用于选定的多账号 provider，恢复其账号池参与调度。属于 L3，因为它可能从单账号切换到多账号轮询并触发重启。Qoder 单账号不显示此操作。

### 4.4 登录 `L` 与添加账号 `A`

```bash
node router.mjs login <provider>
node router.mjs account add <provider>
```

- 使用交互式挂起，不在后台捕获模式下运行。
- 可能打开浏览器、要求粘贴 PAT、启动临时网关或重启已有反代。
- 进入前显示目标和大致流程；离开后重新读取状态。
- Rust 不读取、保存或回显用户输入的 PAT/token。
- 子流程失败或取消后仍恢复 TUI，再显示后端结果。

账号页 `A` 是添加账号；服务页 `A` 是全部启用。底栏和帮助必须始终显示当前上下文，避免依赖肌肉记忆猜错。

## 5. 签到

1. 只有后端明确返回支持且当前可领取时，`c` 才作为可执行动作。
2. 已签到、活动关闭、接口不支持、账号禁用和查询失败分别显示原因。
3. 确认框列出 provider、账号和可能领取的积分；奖励未知时不写 0 奖励。
4. 签到是真实上游写操作，必须限定目标，不默认“八家全部签到”。
5. 没有统一 Node 命令的来源保持只读，不能由 Rust 直接调用私有签名接口。
6. 完成后强制刷新对应 provider 额度，并保留上游返回时间。

自动轮询、启动 TUI、进入额度页和按普通 `r` 刷新均不得签到。

## 6. 健康检查与真实试打

### 6.1 无试打检查 `h`

```bash
node scripts/health.mjs --no-probe
node scripts/health.mjs <provider> --no-probe
```

只检查本地端点、模型列表和凭证等，不发送真实对话。仍可能产生本地 HTTP 请求，因此属于 L1，不是纯内存操作。

### 6.2 真实试打 `P`

```bash
node scripts/health.mjs <provider>
```

- 会发送真实 chat completion，可能消耗积分。
- 可能排队、重试或等待较长时间。
- 默认只选当前 provider，不自动执行八家。
- 确认框显示目标、可能消耗和等待风险。
- 429/排队、401/凭证、超时、上游错误和进程不可达分开显示。

TUI 退出或切换页面不能隐式触发新的试打。

## 7. 日志操作

```bash
node router.mjs logs <provider> <lines>
```

- 行数使用离散档位，避免用户输入任意巨大值。
- 暂停只停止视图跟随，不停止反代进程或磁盘写入。
- 清除视图只清理内存，不删除日志文件。
- 过滤只作用于当前已加载内容。
- 用户向上阅读时暂停跟随；按 End 可回到底部并恢复跟随。
- 读取失败保留上一份内容并标明时间，不把文件暂时不可读显示成空日志。

## 8. 任务队列与互斥

MVP 写任务全局串行：

- 一个写任务运行时，新写请求可以禁用或进入单个明确队列；不能无限排队。
- 同一 provider 重复动作直接提示“已有相同任务在途”。
- 全局动作与所有单项动作互斥。
- 账号切换、登录、添加账号与目标 provider 的启停互斥。
- 只读查询可继续，但写动作完成后必须作废旧代次结果。

默认不自动重试写操作。失败需要用户阅读输出后重新发起，防止重复签到、重复切换或反复启停。

## 9. 操作完成与状态校正

```text
确认 → 执行 → 获取退出码 → 保存有界输出 → 作废旧查询 → 刷新 → 展示真实状态
```

- 退出码非零：任务失败，显示输出；可以做只读校正。
- 退出码为零且刷新成功：显示“已确认”的最新状态。
- 退出码为零但刷新失败：显示“命令完成，状态未确认”。
- 输出含警告：在任务详情保留，不因退出码为 0 丢弃。
- 人类输出不作为状态机的唯一事实来源。

## 10. 退出与中断

### 无写任务

停止轮询，取消只读子任务，恢复终端并退出。

### 有写任务

- 默认建议等待，显示动作和已运行时间。
- 不默认发送 Ctrl+C 或强杀子进程。
- 如果用户离开全屏查看任务，仍保持任务归属和输出。
- 未来若支持强制取消，必须针对具体动作评估原子性并单独确认；MVP 不提供“一键杀所有”。

### Ctrl+C

与 `q` 使用同一退出流程，不绕过终端恢复。交互挂起期间，Ctrl+C 由当前交互 CLI 接收，返回后恢复 TUI。

## 11. 只读与演示模式

### `--read-only`

- 隐藏或禁用 L2–L4 操作。
- 按写键时显示当前模式和退出只读的方式，不静默无响应。
- 不因为用户确认而绕过该模式。

### `--demo`

- 只加载匿名 FixtureBackend。
- 不发现真实 root，不读取真实账号文件，不启动 Node。
- 可以模拟操作、失败和延迟，但顶部必须持续显示 `DEMO`。
- demo 的操作文案不能暗示真实服务已经改变。

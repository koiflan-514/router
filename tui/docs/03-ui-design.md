# 03 界面设计

状态：已实现并完成视觉重构（2026-11-25）  
对应需求：FR-001–FR-055  
原则：键盘优先、状态真实、危险可见、窄屏可用

## 1. 总体布局

标准布局以 120×40 为参考，80×24 必须可用。外壳固定为**五行**：

```text
┌ ◆ Router Control  LOCAL  只读  <root> 状态 2s 前 · 1 错误  12:04:11Z ┐
│ [1]总览 │ [2]服务 │ [3]额度 │ [4]账号 │ [5]日志 │ [6]诊断 │ [7]用量   │
├──────────────────────────────────────────────────────────────────────┤
│ KPI 条 / 主内容：表格、图表、日志或诊断                               │
│                                                                      │
├──────────────────────────────────────────────────────────────────────┤
│ 选中项 / 最近操作 / 局部错误 / 当前任务（上下文摘要）                 │
├──────────────────────────────────────────────────────────────────────┤
│ r刷新 O输出 ?帮助 q退出  │ ↑↓选择 Enter详情 2服务 3额度 5日志         │
└──────────────────────────────────────────────────────────────────────┘
```

- 第 1 行顶栏：品牌、后端（LOCAL/DEMO）、只读标记、root（窄屏折叠）、数据新鲜度、错误数、UTC 时钟。
- 第 2 行页签：当前页高亮 + 下划线；窄屏缩短为 `1总览 2服务 …`，数字键不变。
- 第 3 行主内容：只承担当前页面职责，不堆叠所有指标。
- 第 4 行上下文摘要：选中项状态/最近操作/错误优先；活动写任务显示「运行中 · 不能退出」。
- 第 5 行键位提示：随页面变化；不可用操作在帮助中解释。

## 2. 全局导航与键位

### 2.1 全局键位

| 键位 | 行为 |
|---|---|
| `1`–`7` | 切换总览、服务、额度、账号、日志、诊断、用量分析 |
| `Tab` / `Shift+Tab` | 在页面内可聚焦区域间前后移动 |
| `↑` / `↓`、`j` / `k` | 移动选中项或逐行滚动 |
| `←` / `→`、`h` / `l` | 左右切换列组、水平滚动或调整选项 |
| `PgUp` / `PgDn` | 翻页 |
| `Home` / `End` | 首项/末项或日志顶部/底部 |
| `Enter` | 打开详情、确认当前选择或执行明确标注的主操作 |
| `Esc` | 关闭最上层弹窗、退出筛选或返回；不直接执行副作用 |
| `r` | 刷新当前页面数据源 |
| `O` | 打开最近一次写操作的输出 |
| `?` | 打开上下文帮助 |
| `q` | 请求退出；有活动写任务时先弹出处理说明 |

在文本筛选输入期间，字母键进入输入框，不触发全局操作。弹窗打开时，键位只作用于最上层弹窗。
页面级 `s` 有两种语义：服务页是「同步 opencode」，用量页是「循环排序」；由当前页决定，底栏始终写明。

### 2.2 焦点与选中状态

- 每个页面记住自己的选中 provider、滚动位置和过滤条件。
- 跨页面跳转保留 provider ID；若刷新后该 ID 消失，选择同位置的前一项并提示。
- 焦点、选中行、当前生效账号是三个不同概念，样式必须不同。
- 鼠标不是完成操作的必要条件；MVP 默认不捕获鼠标，以保留终端文本选择。

## 3. 页面一：总览

### 3.1 标准布局

```text
● 运行/启用 5/8  ▓▓▓▓▓░░  ● 配置漂移 1  ● 认证异常 1  ● 可领取/告警 1/2

Provider        开关  进程      认证      客户端    端口   模型  额度
Qoder 国内版    开    ● 运行    1天后到期  已写入    8789    11   ███████░ 96
CodeArts        开    ○ 停止    正常       未写入   10087     —    █████████ 6599
Trae            开    ● 运行    需检查     已写入    7863    29   多账号
WorkBuddy 国内  开    ● 运行    29天后到期 已写入    8787    31   凭证 29 天

右栏（≥120 列）：健康环 · 额度 Top · 近 7 天 sparkline · 待处理（按 x 处理）
! CodeArts：开关=开、进程=停止 → 按 2 进服务，按 5 看日志
```

### 3.2 汇总口径

- `已启用`：`on=true` 的 provider 数。
- `运行`：`up=true` 的 provider 数，与已启用独立计算。
- `认证提醒`：结构化认证状态为 expiring、expired、missing 或 unknown 的数量；具体级别由后端提供。
- `配置漂移`：`on != up`，以及非用户自管配置下的 `on != oc`。
- `可领取`：后端明确返回 claimable 的账号数；未知不计入。

### 3.3 页面操作

- `Enter`：打开 provider 状态详情。
- `2`：进入该 provider 的服务页。
- `3`：进入额度页。
- `4`：进入账号页。
- `5`：进入该 provider 日志。
- `6`：进入诊断并保留该 provider 选择。
- `7`：进入 OpenCode 用量分析。
- 总览不直接执行危险写操作，避免误触。

## 4. 页面二：服务

### 4.1 内容

主表在总览字段基础上显示：

- 控制方式、所有相关 PID；
- opencode 是否用户自管；
- 当前开关与进程是否漂移；
- 选中项认证详情、最近操作和可用下一步。

详情不能只显示“异常”，必须列出具体组合，例如“开关=开、进程=停止、opencode=未写入”。

### 4.2 页面键位

| 键位 | 操作 | 风险级别 |
|---|---|---|
| `u` | 启动选中 provider | 普通写操作 |
| `d` | 停止选中 provider | 普通写操作 |
| `K` | 停止但保留 opencode | 普通写操作 |
| `R` | 重启选中 provider | 普通写操作 |
| `o` | 仅启用选中 provider | 高风险：关闭其他 provider |
| `x` | 关闭选中 provider | 普通写操作 |
| `s` | 同步 opencode | 普通写操作 |
| `A` | 全部启用 | 高风险 |
| `N` | 全部关闭 | 高风险 |
| `L` | 打开选中 provider 日志 | 只读 |

键位不追求与 CLI 首字母完全一致，必须在底栏和确认框中同时显示动作名称。`R` 与全局 `r` 大小写含义不同。

### 4.3 操作中状态

- 选中行显示“正在启动/停止/切换”等任务状态，不提前改成目标状态。
- 任务运行时保留最近一次真实状态，并显示运行时长。
- 任务结束后先刷新，再以最新真实状态替换。
- 动作成功但刷新失败时显示“命令已完成，状态未确认”，不能显示为已验证正常。

## 5. 页面三：额度

### 5.1 分组展示

```text
Qoder 国内版 · example-user · 数据 45s 前
  加购额度   剩余 96 / 共 800 credits   [███████-----] 12%
  签到       活动未开放

CodeArts Agent · 2 个账号 · 数据 45s 前
  account-a  剩余 6599 / 共 6600 credits · 2026-11-24 重置
             即将过期 99 credits · 可领取状态未知

WorkBuddy 国内版 · 数据 45s 前
  凭证剩 29 天 · 续期剩 80 天 · 服务在线
  此来源没有可比较的 credits 余额
```

### 5.2 显示规则

- provider 是顶层分组，账号是第二层，额度桶是第三层。
- 数字使用原单位，最多保留后端有意义的小数位，不用浮点尾数。
- 进度条只在 `total > 0` 且剩余值有效时出现，用 `█░` 绘制；无总量显示 `────`，不编造 `0` 或假百分比。
- 顶部只显示“可查来源数”和“需要处理的提醒数”，**不做跨厂商总额/排行榜**。
- `0`、`null`、接口失败和未查询使用不同文案。
- 后端返回的 `fetchedAt` 与 TUI 收到时间均可展示，避免把网关缓存时间误认为实时时间。
- 额度行新增 `reset_date`（重置日）列：优先显示重置日，没有则退回采集日，两者都缺才显示 `—`。
- WorkBuddy 行明确标注为“凭证有效期/续期有效期”，显示绝对 UTC 到期日；此时状态为“服务在线 · 凭证有效期”，不显示“不支持签到”。额度页标题注明 WorkBuddy 行为凭证天数。

### 5.3 页面键位

- `r`：刷新额度。
- `Enter`：展开账号、额度桶和错误详情。
- `c`：查看签到能力与可领取状态；统一签到命令尚未接入，不执行真实领取。
- `4`：转到相同 provider 的账号页。

## 6. 页面四：账号

### 6.1 图例

| 标记 | 含义 |
|---|---|
| `*` | 当前生效账号 |
| `+` | 参与多账号轮询 |
| `-` | 已停用或不参与轮询 |
| 空白 | 可切换但当前未生效，具体由后端字段决定 |

若某 provider 的 active/enabled 语义不同，UI 必须依据结构化字段和该 provider 能力说明，不自行猜测。

### 6.2 页面内容

- provider、账号 key、脱敏名称、状态、凭证或积分摘要。
- 是否支持切换、恢复整池、添加账号、重新登录。
- 当前选中账号的 dry-run 结果和操作任务状态。
- Qoder 单账号显示“换号请重新登录”，不显示普通槽位切换按钮。

### 6.3 页面键位

| 键位 | 行为 |
|---|---|
| `Enter` | 查看选中账号详情 |
| `v` | 预览切换，即 dry-run |
| `c` | 在已有预览后确认切换，或打开切换确认框 |
| `a` | 恢复该 provider 全部账号参与轮询，需确认 |
| `A` | 添加账号，进入交互式挂起流程 |
| `L` | 登录或重新登录，进入交互式挂起流程 |
| `3` | 转到相同 provider 的额度页 |

## 7. 页面五：日志

### 7.1 布局

- 顶行：provider、尾部行数、跟随/暂停、过滤文本、最近读取时间和截断提示。
- 主区：经过控制序列清理和显示脱敏的日志；级别着色（INF/WRN/ERR/DBG），过滤命中以 `»` 标记，保留滚动条与阅读锚点。
- 详情区：当前过滤匹配数、日志来源说明或读取错误。
- 操作输出与进程日志使用明确标签，不能伪装成同一时间序列。

### 7.2 页面键位

| 键位 | 行为 |
|---|---|
| `p` | 暂停/继续跟随 |
| `f` 或 `/` | 编辑过滤文本 |
| `n` / `N` | 下一个/上一个匹配 |
| `+` / `-` | 增加/减少尾部行数，使用离散档位 |
| `End` | 跳到底部并开启跟随 |
| 手动向上滚动 | 暂停自动跟随，保留阅读位置 |
| `c` | 清除当前显示缓冲，不删除磁盘日志 |
| `2` | 返回相同 provider 的服务页 |

过滤只影响当前已加载文本，不宣称搜索完整历史。达到行数或字节上限时显示“仅显示最近内容”。

## 8. 页面六：诊断

### 8.1 分区

1. 环境：OS、终端、Node、router root、后端可用性。
2. 自检：`doctor` 的退出码和脱敏输出。
3. 健康：端口/模型端点、HTTP 状态、模型数、凭证、错误。
4. 真实试打：目标 provider、模型、耗时、结果和可能费用提醒。
5. 平台限制：当前操作系统不可用的动作及原因。

宽屏为左 checklist + 右输出：每项有通过/警告/错误图标，底部显示 `通过数/总数` meter；
输出区按日志级别着色并提供滚动条。窄屏先放 checklist，再放输出，最小保留 4 行输出。

### 8.2 页面键位

- `d`：运行 doctor。
- `h`：运行无真实对话健康检查。
- `P`：打开真实试打加强确认框。
- `r`：重新读取环境，不自动试打。
- `5`：转到选中 provider 的日志。

## 9. 页面七：用量分析

### 9.1 结构

- 顶部 KPI 卡：会话/步骤、Token、成本、活跃/连续、工具成功率；窄屏截断到 3–4 张。
- 中部每日活动 Sparkline（带范围与峰值）与 Token 构成横条（输入/输出/推理，缓存另计）。
- 工具成功率用 buffer 自绘矩形环 + 图例；下方模型/Provider 表带行内 steps 占比条。
- 模型表按 steps 降序，支持选中滚动和详情；`s` 在步骤/Token/成本/名称间循环排序（纯前端，不重新请求）。
- 总览顶部也使用同一数据源显示 KPI 卡，服务表格保持独立。

### 9.2 数据口径

- 数据来自 OpenCode 官方 `experimental.session.stats`，不使用匿名估算值。
- `steps` 是 OpenCode 会话步骤，不显示为 HTTP 请求数。
- 输入、输出、推理与缓存 Token 分列；缓存不重复累计。
- `cost` 是 OpenCode 上报成本，不等同于积分消耗。
- 工具成功率不代替模型请求成功率。
- OpenCode 不可用或接口失败时保留旧数据并标记 stale；无数据时显示空状态。

### 9.3 页面键位

| 键位 | 行为 |
|---|---|
| `↑↓/jk` | 选择模型 |
| `Enter` | 查看模型 Token、缓存和成本详情 |
| `t` | 切换近 24 小时、近 7 天、近 30 天、全部历史 |
| `s` | 循环排序：步骤 → Token → 成本 → 名称（纯前端，不重新请求） |
| `r` | 刷新当前时间范围 |
| `O` | 查看最近操作输出 |

## 10. 弹窗与流程

### 9.1 普通写操作确认

```text
确认重启 provider？

目标：WorkBuddy 国内版（workbuddy）
影响：停止并重新启动该反代，随后同步客户端配置。
命令：node router.mjs restart workbuddy

[取消]  [确认重启]
Esc 取消 · ←/→ 切换 · Enter 执行当前按钮
```

默认焦点必须是取消。命令用于透明说明，不允许编辑成任意命令。

### 9.2 高风险确认

用于 `on`、`all`、`none`、全局停启和恢复整池：

- 标题明确写出“会影响多个 provider”。
- 列出将被停止、关闭或修改的范围。
- 对“仅启用此家”明确显示其他将被关闭的名称。
- 默认取消；不能用普通 Enter 绕过阅读。
- 不使用容易误触的单键快捷确认。

### 9.3 账号切换

1. 选择账号并按 `v` 进行 dry-run。
2. 展示目标、当前状态、是否重启和配置影响。
3. 用户确认正式切换。
4. 执行后刷新账号、provider 和额度。

### 9.4 真实试打

确认框必须说明：会调用真实模型、可能消耗积分、可能排队或等待较长时间。默认范围为当前单个 provider，不默认全部 provider 一起试打。

### 9.5 退出

- 无活动写任务：直接恢复终端并退出。
- 有活动写任务：显示任务名称和运行时间，推荐等待完成。
- 不把“强制终止写命令”作为默认选项；若后续提供，必须单独评估中途写文件风险。

## 11. 加载、空、错误与 stale

| 场景 | 文案与行为 |
|---|---|
| 首次加载 | `正在读取 provider 状态…`，其他页面可切换 |
| 合法空账号 | `该 provider 当前没有账号`，提供登录说明 |
| 合法空额度桶 | `没有可展示的额度桶`，不等于查询失败 |
| 单家失败 | 行内显示 `不可用`，详情显示原因 |
| 全局后端失败 | 保留导航，显示 Node/root 排查建议 |
| 旧数据刷新失败 | 保留旧值，标记 `stale` 和最后成功时间 |
| 字段缺失 | 显示 `—`，不反序列化失败整页 |
| 平台不支持 | 禁用操作并显示具体平台原因 |
| 只读模式 | 页面可浏览，写键打开“当前为只读模式”说明 |

## 12. 响应式布局

### ≥120 列（Wide）

三栏仪表盘：主表 + 右栏（健康环 / 额度 Top / 近 7 天 sparkline / 待处理），右栏宽 `34%`（夹在 32–56 列）；显示完整键位与说明。

### 80–119 列（Standard）

单栏分层：KPI → 主表 → 待处理；隐藏右栏、次要 PID 列表与控制方式，完整信息进 `Enter` 详情。

### <80 列（Compact）

- 页签缩短，root 与说明文字隐藏。
- 表格只保留状态点/Provider/进程/认证等关键列，其余进详情。
- 弹窗文本自动换行；底部键位只保留最关键项。

### <40 列或 <12 行

显示「终端过小（W×H），至少需要 40×12」的最小界面，仍允许 `q` 和 resize；不强行绘制负宽度布局。高度不足时优先压缩说明与卡片，KPI 与表格始终保留。

## 13. 主题与可访问性

- 唯一颜色语义来源是 `Tone`（Accent/Success/Warning/Error/Info/Muted/Normal），页面不直接写 `Color`。
- 支持 dark/light；默认暗色，可通过参数或环境选择。
- 真彩色、256 色、16 色和无色逐级降级，尊重 `NO_COLOR`。
- `--no-color` 时颜色退化为 BOLD/DIM/REVERSED，并保留不同图标，信息不丢失。
- 状态同时使用文本/符号和颜色，错误不只显示红色。
- Unicode 模式用 `● ✓ ! ▲ ✖ ? █ ░`；`--ascii` 时边框、选中符、进度条（`#+.`）、sparkline 与矩形环全部 7-bit。
- `Glyphs` 统一管理图标；中文按显示宽度（CJK 占 2 列）截断并补省略号，数字右对齐。
- 长名称省略中间或末尾时，完整值仍可在详情查看。
- 不频繁闪烁；任务状态以文本和简短 spinner 表示。

## 14. 帮助页

帮助必须按上下文组织：

1. 全局导航；
2. 当前页面键位；
3. 当前 provider 支持和限制；
4. 状态符号图例；
5. 写操作影响；
6. 当前模式：demo/read-only/真实后端。

帮助只读，按 `Esc`、`?` 或 `q` 返回，不因打开帮助而刷新或执行动作。

## 15. 禁止的交互

# 02 产品需求

状态：设计基线  
适用范围：`router-tui` MVP 与明确的后续方向

## 1. 背景

当前八家 provider 已能由根目录 CLI 管理，但日常运维分散在 `list`、`account`、`credits`、`health`、`logs` 和多个启停命令中。用户需要在终端内快速回答：

- 哪些 provider 已启用、正在运行并写入客户端？
- 哪个账号正在生效，哪些账号参与轮询？
- 凭证是否将到期，积分是否即将耗尽或过期？
- 操作是否成功，失败时应该看哪份日志？
- 当前平台是否支持想执行的动作？

## 2. 目标用户

### 主要用户

本机 router 的维护者：熟悉基本终端操作，需要同时管理多个 AI 编程订阅和反代。

### 次要用户

- 在 Linux 或 Windows 上演示、测试界面但不持有真实凭证的开发者。
- 排查单一 provider 故障的使用者。

MVP 是单机单用户工具，不为团队管理员、审计员或远程租户设计。

## 3. 用户故事

1. 作为维护者，我希望打开一个界面就看到八家服务状态，以便发现开关、进程和配置漂移。
2. 作为维护者，我希望按 provider 启停或重启，以便处理卡死和释放资源。
3. 作为维护者，我希望看到“仅启用此家”的真实影响，以免误关其他服务。
4. 作为维护者，我希望查看并切换账号，以便在账号过期或限流时恢复服务。
5. 作为维护者，我希望区分余额、凭证天数和签到状态，以便正确理解可用额度。
6. 作为维护者，我希望从异常直接进入日志或诊断，以便缩短排障路径。
7. 作为开发者，我希望使用匿名演示数据，以便在没有凭证的机器上测试全部页面。
8. 作为 Windows/Linux 用户，我希望键位和状态含义一致，以便跨系统使用。

## 4. 范围

### 4.1 MVP 必须包含

- 七个页面：总览、服务、额度、账号、日志、诊断、用量分析。
- 八家 provider 的真实只读状态。
- 匿名 `--demo` 数据后端。
- 手动和定时刷新、局部失败、数据时间和 stale 标识。
- 单 provider 启停、重启、开关、同步和全局操作。
- 账号查看、切换预览、正式切换、恢复整池。
- 登录流程的终端挂起与恢复。
- 日志查看、筛选、暂停、跟随和有界缓冲。
- doctor、无真实对话健康检查；显式端到端试打。
- 危险操作确认、任务互斥、操作输出和退出保护。
- Windows/Linux 构建与自动化测试。

### 4.2 后续可以考虑

- 结构化模型目录浏览与模型可用性检查。
- OpenCode 官方会话统计：会话/步骤、Token、缓存、活动、工具成功率和模型/Provider 聚合。
- 请求级 TTFT/P75、逐请求日志和路由尝试追踪。
- 配置导出、诊断报告和匿名支持包。
- 远程主机后端，但必须先有认证、授权和传输安全设计。
- 更多 provider，由后端数据驱动而非复制页面。

### 4.3 明确不做

- 替代 `router.mjs` 或重新实现其进程树清理算法。
- 在 Rust 中直接修改各厂商凭证和账号池。
- 自动签到、自动真实试打、自动重启循环。
- 多用户、RBAC、团队计费、虚拟 Key 管理。
- 任意 Shell 输入和任意命令执行。
- 默认采集提示词、响应内容或身份信息。
- 把不同厂商积分汇总成统一资产或金额。

## 5. 功能需求

### 5.1 总览与状态

| ID | 需求 | 验收摘要 |
|---|---|---|
| FR-001 | 必须列出后端返回的全部 provider | 八家均可出现；新增 provider 不需要新增页面 |
| FR-002 | 必须分别显示启用开关、进程、opencode 和认证状态 | 不用单个“正常”覆盖四个状态 |
| FR-003 | 必须显示端口、PID、模型数和数据时间 | 未知显示 `—`，不能当成 0 |
| FR-004 | 必须汇总运行数、认证异常、配置漂移和可处理提醒 | 汇总可由明细推导 |
| FR-005 | 必须能从选中 provider 进入服务、日志或诊断 | 保留当前 provider 焦点 |
| FR-006 | 单家查询失败不得清空其他 provider | 显示局部错误和旧数据时间 |

### 5.2 服务控制

| ID | 需求 | 验收摘要 |
|---|---|---|
| FR-010 | 必须支持 `up/down/restart` | 使用真实 CLI 参数，不经 Shell 拼接 |
| FR-011 | 必须支持 `on/off/all/none/sync` | 文案准确描述配置和进程副作用 |
| FR-012 | 必须支持 `down --keep-oc` | 与普通停止区分 |
| FR-013 | 副作用操作必须确认 | 默认取消，可看到目标和影响 |
| FR-014 | 同一 provider 的写操作必须互斥 | 连按不会重复启动或切换 |
| FR-015 | 操作后必须重新查询真实状态 | 不仅凭退出码把 UI 标成成功状态 |
| FR-016 | 操作输出必须可查看 | 成功、失败和仍在执行可区分 |

### 5.3 额度

| ID | 需求 | 验收摘要 |
|---|---|---|
| FR-020 | 必须按 provider/账号展示余额、总量、单位和重置信息 | 缺失字段显示 `—` |
| FR-021 | 必须显示来源可用性和失败原因 | 未登录、服务未运行、接口失败可区分 |
| FR-022 | 必须显示数据采集时间和 stale 状态 | 旧数据不能冒充实时结果 |
| FR-023 | 签到按钮必须由后端能力决定 | 不支持时说明原因，不显示可点击假象 |
| FR-024 | 签到必须显式确认 | 刷新绝不触发签到 |
| FR-025 | 即将过期和额度耗尽必须醒目提示 | 不仅依赖颜色 |

### 5.4 账号与登录

| ID | 需求 | 验收摘要 |
|---|---|---|
| FR-030 | 必须显示当前生效、参与轮询、停用和可切换状态 | 符号含义有图例 |
| FR-031 | 切换前必须支持 dry-run | 用户先看到目标和影响 |
| FR-032 | 正式切换必须使用现有 account 命令 | 不直接复制或修改凭证文件 |
| FR-033 | 恢复整池必须限定到选定 provider | 不影响其他 provider |
| FR-034 | 登录必须能交还终端给交互式 CLI | 完成后恢复全屏、raw mode 和状态 |
| FR-035 | 单账号与多账号交互必须不同 | Qoder 不显示普通槽位切换 |

### 5.5 日志与诊断

| ID | 需求 | 验收摘要 |
|---|---|---|
| FR-040 | 必须能选择 provider 和日志尾部行数 | 使用现有 logs 能力 |
| FR-041 | 必须支持过滤、暂停、跟随和滚动 | 新日志不抢夺手动滚动位置 |
| FR-042 | 日志缓冲必须有上限 | 长时间运行不无限增长 |
| FR-043 | 日志渲染前必须清理控制序列和常见密钥 | 防止终端转义注入和意外泄密 |
| FR-044 | 必须支持 doctor 和无对话健康检查 | 不消耗模型额度 |
| FR-045 | 真实试打必须单独确认 | 明示可能消耗额度和等待时间 |
| FR-046 | 健康失败必须保留具体错误 | 不仅显示红灯 |

### 5.6 用量分析

| ID | 需求 | 验收摘要 |
|---|---|---|
| FR-060 | 必须使用 OpenCode 官方统计接口，不读数据库或伪造请求数据 | `experimental.session.stats` 返回真实会话统计 |
| FR-061 | 必须区分 steps 与 HTTP 请求数 | 页面和帮助明确 steps 语义 |
| FR-062 | 必须展示会话/提示、Token 构成、缓存、工具成功率和模型/Provider 聚合 | 可从官方 stats 字段直接验证 |
| FR-063 | 必须支持 24h/7d/30d/全部历史并显示当前范围 | `t` 切换，查询参数随范围变化 |
| FR-064 | 必须有每日活动和模型详情，但无数据时显示空状态 | 无数据不生成随机曲线 |
| FR-065 | 必须标明 OpenCode 上报成本，不与积分余额混淆 | cost 不折算积分、不推断实际扣费 |
| FR-066 | 用量接口失败不得影响服务管理 | 保留旧数据并标记 stale，其他页可用 |

### 5.7 通用交互

| ID | 需求 | 验收摘要 |
|---|---|---|
| FR-050 | 必须支持键盘完成全部 MVP 操作 | 不依赖鼠标 |
| FR-051 | 必须提供帮助、空状态、错误状态和加载状态 | 用户始终知道下一步 |
| FR-052 | 必须支持 `--demo` 和 `--read-only` | demo 不访问真实后端；只读模式禁用写操作 |
| FR-053 | 必须支持无色和 ASCII 降级 | 状态不只靠颜色或特殊字形 |
| FR-054 | 终端尺寸变化必须正确重排 | 不崩溃、不输出无限控制字符 |
| FR-055 | 正常、错误和 panic 退出都应恢复终端 | cursor、raw mode、alternate screen 恢复 |

## 6. 非功能需求

| ID | 类别 | 要求 |
|---|---|---|
| NFR-001 | 平台 | Windows/Linux 原生构建和测试，具体目标见跨平台文档 |
| NFR-002 | 响应 | 键盘处理和网络/子进程等待解耦，后台请求时界面仍可操作 |
| NFR-003 | 负载 | 同一数据源不并发重复轮询；慢响应不能触发请求堆积 |
| NFR-004 | 资源 | 日志和任务输出有界；默认不持续运行真实试打 |
| NFR-005 | 安全 | 参数数组、操作白名单、危险确认、敏感信息脱敏 |
| NFR-006 | 隐私 | 不上传遥测，不持久化凭证，不提交真实 fixtures |
| NFR-007 | 兼容 | JSON 增量变更；未知字段忽略；缺失字段有默认值 |
| NFR-008 | 可测试 | UI 与后端解耦，无真实账号也能完成 CI |
| NFR-009 | 可维护 | 状态语义集中定义，不在多个页面各写一套判断 |
| NFR-010 | 可发布 | 构建可重复，发布包不含凭证、日志、target 或本机绝对路径 |

## 7. 额度与单位规则

- `credits` 只表示对应厂商返回的计数单位，不隐含人民币、美元或跨厂商兑换关系。
- 可以在单账号内计算 `remaining / total`；总量缺失或小于等于 0 时不显示百分比。
- 不做八家积分总和，不做跨厂商排行榜，不把 WorkBuddy 凭证天数转换为积分。
- `remaining = 0` 只表示接口返回 0，不自动推断所有模型不可调用；若上游提供额外说明，应保留说明。
- `expiring` 与 `remaining` 分开显示，重置日和到期日不得混用。
- 签到状态至少区分：已签到、可领取、活动未开放、接口不支持、账号禁用、未知。
- WorkBuddy 没有 credits 余额接口；其“额度”是 access token 与 refresh token 的有效天数。页面必须显示“凭证有效期/续期有效期”、UTC 绝对到期时间和“服务在线”，不能显示成普通 credits，也不能以“不支持签到”代替额度状态。
- WorkBuddy 国际版上游可能把 access/refresh 的到期时间设成同一天，界面应如实显示相同日期，不能去重制造“缺少数据”的假象。

## 8. 状态显示规则

- `null`、请求失败、尚未查询和真实数值 0 是四种不同状态。
- 数据请求失败时可以保留上一份成功数据，但必须标记“数据已过期”及最后成功时间。
- `models: null` 表示未查询或进程未运行，不显示“0 模型”。
- 认证结构化状态优先于描述文本；不得靠匹配中文 label 推导过期。
- 运行进程不代表凭证有效，凭证有效不代表 opencode 已配置。

## 9. MVP 完成定义

MVP 只有同时满足以下条件才算完成：

1. FR-001 至 FR-055 均有实现或经明确批准的范围调整。
2. NFR-001 至 NFR-010 有对应测试或人工验收记录。
3. Windows/Linux CI 通过，关键终端人工矩阵通过。
4. 无凭证 CI 不访问真实账号、不执行真实写操作。
5. 文档、帮助文案和实际命令语义一致。
6. 发布物能够清晰报告 Node/router 缺失、平台不支持、单家失败和全局后端失败。
